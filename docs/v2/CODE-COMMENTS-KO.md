# 한국어 주석 규약 (`sbmig/` 코드)

`sbmig/` 코드의 docstring은 한국어 부분, 빈 줄, 영어 부분 순서로 쓴다.

- 한국어: 사람이 읽는 주석이다. 다음 담당자는 한국어만 읽는다. 개발자가 코드에 직접 남기는 주석처럼 쓴다.
- 영어: 코드를 고치는 쪽이 참고하는 작업 메모다. 한국어 아래 빈 줄을 두고 쓴다.

`tests/docs/test_korean_comments.py`가 이 규약을 검사한다.

## 1. 형식

1. 모듈 docstring은 한국어 블록, 빈 줄, 영어 메모 순서로 쓴다.
2. 공개 클래스와 함수(이름이 `_`로 시작하지 않는 최상위 정의)의 docstring에는 한국어가 있어야 한다. 순서는 모듈과 같다.
3. 인라인 주석은 한국어 한 줄로 쓴다. 같은 내용을 영어로 한 번 더 적지 않는다.
4. 영어 메모는 필요할 때만 둔다. 한국어와 같은 말이면 쓰지 않는다(6절).
5. 코드, 문자열, 로그 문구, 프롬프트 `.md`는 주석을 고칠 때 건드리지 않는다.

## 2. 분량

| 대상 | 분량 | 쓰는 내용 |
|---|---|---|
| 모듈 docstring | 1~2줄 | 이 파일이 무슨 일을 하는지만 쓴다. 목록은 쓰지 않는다 |
| 클래스 docstring | 1~2줄 | 이 클래스가 하는 일 |
| 함수 docstring | 첫 줄에 하는 일. 필요하면 서너 줄까지 | 값이 없을 때 반환하는 것, 던지는 예외, 동작이 달라지는 조건, 호출하는 쪽이 먼저 해야 하는 일 |
| 인라인 주석 | 1줄, 길어도 2줄 | 지금이 어떤 경우이고 그래서 어떻게 하는지, 또는 코드만 봐서는 알 수 없는 이유 |

한 줄을 고집하지 않는다. 읽는 사람이 알아야 하는 정보는 넣는다. 다만 문단으로 길게 쓰지 않고, 변경 경위나
코드만 봐도 아는 내용은 쓰지 않는다. 규칙이나 단계가 여러 개면 `- ` 목록이나 번호 목록으로 나눈다.
이름과 본문 몇 줄로 다 드러나는 비공개 함수에는 docstring을 두지 않아도 된다.

모듈 docstring의 한국어는 이 파일이 하는 일만 말한다. 어디서 호출하는지, 내부 순서, 지켜야 하는 규칙은
영어 메모에 둔다(6절). 한국어에서 뺀 내용이 영어 메모에 없으면 영어 메모에 짧게 옮겨 쓴다.
예외는 최상위 `sbmig/__init__.py` 하나다. 이 파일은 패키지 지도라서 패키지마다 한 줄씩 한국어로 둔다.

## 3. 쓰는 법

읽는 사람은 이 프로젝트를 처음 보는 개발자다. 주석만 읽고 이 코드가 무엇을 하는지 알 수 있어야 한다.

- 첫 문장에 하는 일을 쓴다. 함수는 "~한다.", 클래스는 "~하는 클래스.", 모듈은 "~하는 모듈."로 끝낸다.
- 주어와 목적어가 있는 온전한 문장으로 쓴다. "없으면 ''."처럼 끊어 쓰지 않고 "값이 없으면 빈 문자열을 반환한다."로 쓴다.
- 간단한 함수는 한 문장으로 끝낸다.
- 프로젝트 안에서만 통하는 말은 풀어 쓴다(4절). 약어는 "오류 서명(L2)"처럼 뜻을 함께 쓴다.
- 지금 코드와 상관없는 설명은 쓰지 않는다. "~로는 쓰지 않는다", "예전에는 ~였다" 같은 문장이다.
- 인라인 주석은 지금이 어떤 경우이고 그래서 어떻게 하는지를 쓴다. 이유가 필요하면 짧은 문장으로 덧붙인다.
  마지막 문장의 마침표는 생략한다.
- 조사는 앞말에 붙인다. `KB에`, `pom을`, `` `match`를 ``.
- 식별자, 설정 키, 파일명, 로그 문구는 원문 그대로 쓴다.
- 쓰지 않는 표기: 줄표(`—`), 화살표(`→`), 굵게(`**`), 세미콜론으로 문장 잇기, 괄호 안 괄호. 단계를 나열할 때만 `->`를 쓴다.
- 쓰지 않는 내용: 버전 태그(`v2.1…`), 날짜, 리뷰나 라운드 번호, 항목 번호, 어느 실행에서 발견했는지 같은 경위.
  이유가 필요하면 현재 사실로 쓴다. 예: "Windows는 읽기 전용 fd의 fsync를 거부한다"
- 쓴 뒤에 소리 내어 읽듯이 한 번 더 읽는다. 옆자리 동료에게 그렇게 말하지 않을 문장이면 고친다.
  영어 어순을 뒤집은 문장, "수행", "해당", "상기", "~하며 ~하고 ~하여"로 이어지는 문장이 그런 문장이다.

### 3.1 보자마자 알 수 있게 쓴다

주석은 옆자리 동료가 "이 코드 뭐 하는 거예요?"라고 물었을 때 말로 해 주는 대답처럼 쓴다.
핵심만 말하고, 한 번 읽으면 이해되게 쓴다. 기준이 되는 주석은 `sbmig/analyze/build_tool.py`의 이 줄이다.

```python
# pom이 있으면 Maven으로 본다. 함께 있는 Gradle, Ant 파일은 무시하고 reason에 "ignored"만 남긴다
if _has_any(ws, ("pom.xml",)):
```

1. 한 문장에 한 가지만 쓴다. 문장이 길어지면 끊는다. "~하고, ~하며, ~하므로 ~한다"로 잇지 않는다.
2. 어떤 경우인지 먼저 쓰고, 그래서 어떻게 하는지를 쓴다. "pom이 있으면 Maven으로 본다."
3. 구현 용어 대신 뜻을 쓴다. "유한하지 않은 float"가 아니라 "NaN과 무한대", "트리"가 아니라 "프로젝트"다.
4. 핵심만 쓴다. 무엇을 하는지가 핵심이다. 누가 호출하는지, 비용, 내부 순서, 설정 기본값은
   이 코드를 쓰거나 고치는 사람에게 꼭 필요할 때만 쓴다.
5. 함수 이름이나 시그니처를 우리말로 옮긴 문장은 쓰지 않는다. 읽는 사람이 궁금한 것을 쓴다.
6. 한 문장은 되도록 한 줄 안에서 끝낸다. 60자를 넘으면 두 문장으로 나눌 수 있는지 본다.

| 고치기 전 | 고친 뒤 |
|---|---|
| dict, list, tuple 안의 유한하지 않은 float를 깊이와 상관없이 None으로 바꾼 값을 반환한다. | 값 안의 NaN과 무한대를 None으로 바꿔서 반환한다. dict, list, tuple은 안쪽까지 모두 바꾼다. |
| 이름 중 하나인 파일이 트리에 있는지 확인한다. 확인 비용이 적은 루트를 먼저 보고, 없으면 하위 전체를 찾는다. | ``names`` 중 하나라도 프로젝트 안에 있으면 True를 반환한다. 루트부터 보고, 없으면 하위 폴더까지 찾는다. |
| 빌드 오류 묶음에 맞는 저장된 수정 스크립트를 찾는다. | 이 빌드 오류를 고친 적이 있는지 KB에서 찾는다. |
| 케이스 ID가 같아도 오류 서명(L2)이 다르면 다른 케이스이므로 건너뛴다 | 케이스 ID가 같아도 오류 서명(L2)이 다르면 다른 케이스다. 건너뛴다 |
| zip slip 공격을 막기 위해 항목 경로가 임시 디렉토리 밖을 가리키면 거부한다 | 경로가 임시 디렉토리 밖을 가리키는 항목은 거부한다(zip slip 공격 방지) |

Maven과 쿠버네티스 용어는 영어 그대로 쓴다(pom, BOM, scope, classifier, dependencyManagement, Job, ConfigMap, Secret, PVC).

| 쓰지 않는 말 | 대신 쓰는 말 |

| 사본 | 복사본 |
| 꼬리 | 뒷부분 |
| 사다리 | 시도 순서(재사용 -> 보강 -> 신규) |
| 채점 | 시도 결과 평가 |
| 판정 | 결과, 판단 |
| 사실(facts) | 정보 |

| 쓰지 않는 말 | 대신 쓰는 말 |

| 부른다, 불린다 | 호출한다, 호출된다 |
| 돈다, 돌린다 | 실행된다, 실행한다 |
| 적는다, 적힌 | 기록한다, 기록된 |
| 예외를 올린다 | 예외를 던진다 |
| 묻는다 | 조회한다, 확인한다 |
| 닿는다 | 적용된다, 전달된다 |
| 훑는다 | 검사한다, 순회한다 |
| 창구, 틀, 자리, 지문, 낱말, 글자 | 파사드, 템플릿, 슬롯, 해시, 단어, 문자 |
| 시험 | 테스트 |
| 옛 규칙, 옛 이미지 | 이전 규칙, 이전 이미지 |
| 이미지에 굽는다 | 이미지에 포함한다 |
| 영수증 | 접수 정보 |
| 최선 노력 | 실패해도 계속 진행한다 |

## 6. 영어 메모

한국어만 읽는 사람은 빈 줄에서 멈추면 된다. 영어 메모는 코드를 고칠 때 필요한 내용만 둔다.

- 남기는 것: 이 함수가 지키는 규칙과 순서, 깨지면 안 되는 조건, 실패할 때 반환하거나 던지는 것, 다른 모듈과 맞물린 부분,
  플랫폼 제약, 도구를 실제로 돌려 확인한 사실, 필드와 값의 뜻
- 모듈을 어디서 호출하는지, 모듈 전체에 걸친 규칙도 영어 메모에 둔다. 한국어 모듈 docstring은 하는 일만 말한다
- 빼는 것: 어떻게 발견했는지, 어느 리뷰에서 나왔는지, 예전에는 어땠는지, 날짜, 한국어 줄이나 시그니처를 그대로 반복한 문장
- 계약 위치(`docs/INTERFACES.md "v2.1z-ce"` 같은 표기)는 영어 메모에만 둔다. docstring 하나에 한 번이면 된다
- 버전 표기, 날짜, 리뷰 번호는 한국어 줄, 한국어 인라인 주석, 구분선 제목에는 쓰지 않는다
- 구분선(`# ---- …`)의 제목은 짧은 한국어로 쓴다

## 5. 예시

다듬은 예시 파일: `sbmig/analyze/build_tool.py`, `sbmig/web/jsonsafe.py`, `sbmig/core/stage.py`, `sbmig/kb/store.py`.

함수 docstring:

```python
def _src_tail(path: str) -> str:
    """파일 경로에서 ``src/`` 이후 부분만 잘라서 반환한다."""

def finite_json(value: Any) -> Any:
    """값 안의 NaN과 무한대를 None으로 바꿔서 반환한다.
    dict, list, tuple은 안쪽까지 모두 바꾼다."""

def lock(self):
    """여러 프로세스가 KB를 동시에 고치지 않도록 잠금을 건다.
    같은 프로세스는 잠금을 다시 잡을 수 있다."""

def match(self, cluster, ws=None, profile=None) -> KBMatch:
    """이 빌드 오류를 고친 적이 있는지 KB에서 찾는다. 수정 루프가 라운드마다 호출한다.
    저장된 스크립트가 있으면 그 스크립트와 지난번 해결 내용을 반환한다. 처음 보는 오류면 빈 결과다.
    사람이 차단해 둔 케이스는 스크립트 대신 차단 결정을 반환한다.
    조회에 실패해도 예외를 던지지 않는다. 수정 루프는 계속돼야 한다.

    CaseHit status: active = proven, candidate = unverified ..."""
```

클래스 docstring:

```python
class BuildToolDetection:

```

```python
오케스트레이터, 플릿, 웹 서버가 모두 이 모듈로 KB를 쓴다.

The facade over :class:`sbmig.errors.cases.CaseStore` ...
"""
```

```python

best = self.cases.best(cid, scope)
```
